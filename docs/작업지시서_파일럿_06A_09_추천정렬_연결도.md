## 2. 작업 6A — 규칙 기반 추천 정렬

### 목적
전담사회복지사가 생활지원사 보고를 읽고 연계처를 고를 때, 보고 내용과 관련 있는 종류의 연계처를 목록 위로 올려 찾는 수고를 줄인다.

### 동작
1. 규칙 파일 `data/recommend_rules.json`을 만든다. 연계처 종류(`category`)마다 단어 목록을 둔다. 현재 종류는 `돌봄`·`생계`·`식사`·`의료`·`정서`·`주거` 6개다. 초안(전담 검토 전 시작값, 자유롭게 보완):
   ```json
   {
     "version": 1,
     "rules": {
       "식사": ["식사", "밥", "끼니", "반찬", "도시락", "굶", "입맛", "냉장고"],
       "의료": ["병원", "약", "아프", "통증", "진료", "어지러", "넘어", "낙상", "혈압", "당뇨", "퇴원"],
       "돌봄": ["거동", "혼자", "씻", "목욕", "청소", "수발", "보호자"],
       "주거": ["집", "보일러", "난방", "수리", "곰팡이", "누수", "전기", "가스", "추위", "더위"],
       "생계": ["돈", "생활비", "공과금", "체납", "월세", "수입", "통장"],
       "정서": ["외로", "우울", "말벗", "눈물", "기운", "사별", "잠을"]
     }
   }
   ```
2. 연계처 목록 API `GET /api/case/:id/linkage-targets`가 목록을 돌려줄 때, 그 어르신의 **보고 원문**(`notes` 중 `type: 'field_report'`)을 규칙과 비교한다
   - 대상 보고: **아직 연계로 이어지지 않은 최근 보고**. 보고와 연계의 연결 필드(작업 7)를 써서 정한다. 판단이 애매하면 최근 보고 1건으로 하고 인수인계에 적는다
   - 단어가 들어 있으면(부분 일치) 해당 종류 점수 +1. 같은 단어 반복은 1번만 센다
3. 응답의 각 연계처에 다음을 붙인다(기존 필드는 그대로)
   - `recommend: { score, matched: ["밥", "냉장고"] }` — 점수 0이면 `null`
4. 정렬: 점수 높은 순 → 기존 순서(시군 → 권역 → 경남 전체). 점수 0인 연계처도 **모두 그대로 보여준다**. 걸러내지 않는다
5. 시군 범위 필터(작업 7: 케이스 시군 + 포함 권역 + 경남 전체)는 정렬보다 먼저 그대로 적용한다

### 화면 (2층 연계처 선택 부분)
- 점수가 있는 연계처에 **"보고 내용과 관련"** 표시와, 걸린 단어를 작게 보여준다(예: `관련: 밥, 냉장고`). 왜 위에 왔는지 전담이 알 수 있어야 한다
- 점수가 하나도 없으면 아무 표시 없이 기존 순서로 보여준다
- "추천" 이라는 말 대신 "관련"을 쓴다. 시스템이 판단했다는 인상을 주지 않기 위함이다
- 선택 버튼·결과 기록 등 기존 동작은 바꾸지 않는다

### 기록 (향후 AI 판단 근거)
- 연계를 생성할 때 linkage에 `recommendSnapshot: { rank, score, matched, rulesVersion }`를 저장한다. 고른 연계처가 그때 목록 몇 번째였고 점수가 얼마였는지를 남기는 것이다. 표시되지 않았으면(점수 0) `score: 0`
- 이 값은 화면에 보여주지 않는다. 집계 화면도 만들지 않는다

### 완료 조건
- [ ] 보고에 "밥을 거르신다"가 있는 어르신 → `식사` 종류 연계처가 맨 위, `관련: 밥` 표시
- [ ] 단어가 두 종류에 걸리면(예: "병원 가는 길에 넘어지셔서 밥을 못 드심") 점수 순으로 정렬
- [ ] 보고가 없거나 단어가 없으면 기존 순서·표시와 같음(이전 화면과 비교)
- [ ] 점수 0인 연계처도 목록에 모두 남음(건수 비교)
- [ ] 시군 밖 연계처는 여전히 목록에 없고, 저장 시 400(작업 7 검증 재통과)
- [ ] 연계 생성 후 linkage에 `recommendSnapshot` 저장
- [ ] worker 세션에서 `/api/case/*` 403 유지(작업 3 검증 재통과)
- [ ] 서버 밖으로 나가는 요청 0건(코드 검색으로 확인)

## 3. 작업 9 — 어르신 연계 연결도

### 목적
어르신 한 명의 보고·연계 흐름을 텍스트 목록과 함께 **도형으로** 보여준다. 어르신 단위만 그린다. 기관 전체 연결망은 그리지 않는다.

### 위치
2층의 어르신 서랍(또는 어르신 상세 화면) 안, 기존 연계 목록 **위**에 접고 펼 수 있는 영역으로 둔다. 기본은 펼침. 기존 텍스트 목록은 지우지 않는다(도형은 보조).

### 그림
```
[생활지원사 보고]──▶[어르신]──▶[연계처 A]  ● 접수
  (날짜)                   ├──▶[연계처 B]  ○ 결과 미기록
                           └──▶[수행기관 B] ◐ 수락 대기
```
- 왼쪽: 보고(최근 3건까지, 날짜). 연계로 이어진 보고는 선으로 해당 연계와 잇는다
- 가운데: 어르신(가상 이름. 실데이터 단계에서는 가린 이름으로 바뀜 — 이번 범위 아님)
- 오른쪽: 연계(외부 연계처·다른 수행기관 의뢰). 상자 안에 연계처명, 상태를 **글자와 모양으로** 표시
  - 외부 연계: 결과 미기록 / 접수 / 미접수
  - 내부 의뢰: 수락 대기 / 수락 / 반려
  - 색만으로 상태를 구분하지 않는다(글자 필수)
- 연계가 없으면 "아직 연계가 없습니다" 한 줄만 보여준다
- 상자를 누르면 기존 연계 카드(텍스트)로 스크롤한다. 도형 안에서 편집·기록하지 않는다

### 구현
- 손으로 쓴 인라인 SVG. 외부 라이브러리 없음
- 데이터는 이미 내려오는 케이스·연계 데이터로 그린다. 새 API를 만들지 않는다(필요하면 기존 응답에 필드 추가까지만)
- 휴대폰(375·390px): 세로 배치(보고 → 어르신 → 연계가 위에서 아래로). PC(1024px 이상): 가로 배치
- 라이트·다크 모드 모두 읽히게

### 완료 조건
- [ ] 캡처용 대표 예시 4명(가상어르신 하나·둘·셋·넷)이 각각 맞는 상태로 그려짐
- [ ] 연계 없는 어르신 → 안내 한 줄
- [ ] 연계 5건 이상이어도 겹치지 않음(시드로 임시 확인 후 원복)
- [ ] 375·390·1280px에서 가로 스크롤 없음
- [ ] 상자 누르면 해당 연계 카드로 이동
- [ ] 기존 연계 목록·결과 기록·수락/반려 동작 변화 없음
